# Science Lounge: установка

Сайт лектория школы «Летово»: афиша, журнал выпусков, новости науки, конференция, админка. Здесь весь исходный код. Ничего докупать и подключать не нужно: база SQLite лежит в одном файле, шрифты и карта уже внутри.

## Что понадобится

- **Node.js 22 или новее** (проверка: `node -v`). Скачать: https://nodejs.org (кнопка LTS подойдёт, если там 22+).
- Терминал: на Mac «Терминал», на Windows PowerShell, на Linux любой.
- Интернет только на время установки и для автоподбора новостей.

Docker и отдельная база данных не нужны.

## 1. Запуск на своём компьютере (5 минут)

Распакуйте архив, откройте терминал в папке `science-lounge` и выполните по порядку.

**Mac / Linux**

```bash
npm ci
cp .env.example .env
```

**Windows (PowerShell)**

```powershell
npm ci
Copy-Item .env.example .env
```

Откройте файл `.env` в любом редакторе и поменяйте две строки:

```
SITE_URL=http://localhost:3000
TRUST_PROXY=false
```

Создайте администратора (пароль не короче 10 знаков) и запустите сайт:

```bash
npm run admin:create -- ваша@почта.ру "Ваше имя" "длинный-пароль"
npm start
```

Откройте в браузере:

- сайт: http://localhost:3000
- админка: http://localhost:3000/admin

Остановить сайт: `Ctrl+C` в терминале.

### Чтобы сайт не был пустым

```bash
npm run seed:demo      # образцы выпусков, лекторов, конференции и команды; в админке помечены «демо»
npm run seed:clear     # убрать образцы перед настоящим наполнением
```

Дальше всё делается в админке. Подробная инструкция для организаторов со скриншотами: `docs/KAK-VESTI-SAYT.md`.

### Проверка, что всё в порядке

```bash
npm test
```

Должно быть `fail 0`. Тесты используют временную базу и ваши данные не трогают.

## 2. Выкладка в интернет

Нужны сервер (VPS, подойдёт самый дешёвый: 1 ядро, 1–2 ГБ памяти, 20 ГБ диска) и домен. Для школы лучше российский провайдер (Timeweb Cloud, Selectel, Yandex Cloud): персональные данные остаются в России.

Кратко, через Docker на Ubuntu 22.04/24.04:

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-v2 unzip
unzip science-lounge-source.zip -d /opt && cd /opt/science-lounge
cp .env.example .env
nano .env
```

В `.env` заполните:

```
SITE_URL=https://ваш-домен.ру
SITE_DOMAIN=ваш-домен.ру
ADMIN_EMAIL=вы@школа.ру
ADMIN_PASSWORD=длинный-пароль-10+знаков
```

В DNS добавьте запись `A`: ваш домен на IP сервера. Затем:

```bash
docker compose up -d --build
docker compose logs -f app
```

Сертификат HTTPS получится сам, как только домен начнёт указывать на сервер. Админка: `https://ваш-домен.ру/admin`. После первого входа удалите `ADMIN_PASSWORD` из `.env` и выполните `docker compose up -d`.

Данные (база, фото, копии) лежат в томе Docker и переживают обновления. Вариант без Docker (systemd + nginx), Telegram-бот для обращений, аналитика, копии и чек-лист перед запуском: `docs/DEPLOY.md`.

## 3. Настройки в `.env`

| Параметр | Что делает |
| --- | --- |
| `SITE_URL` | публичный адрес; с `https://` включаются защищённые cookie и HSTS |
| `PORT`, `HOST` | порт и адрес, на котором слушает сайт (по умолчанию 3000 и 127.0.0.1) |
| `TRUST_PROXY` | `true`, если сайт стоит за nginx, Caddy или Docker-прокси; на своём компьютере `false` |
| `DATA_DIR` | где лежат база, фото и копии (по умолчанию папка `data`) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | первый администратор, создаётся при самом первом запуске |
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | уведомления организаторам о новых обращениях (необязательно) |
| `NEWS_AUTO` | `true`: сайт сам подбирает новости науки из открытых RSS-лент, `false`: только вручную |
| `BACKUP_ENABLED` | копия базы и фото раз в сутки в `data/backups` |

Источники автоновостей и выключатель также есть в админке: «Настройки» → «Новости науки».

## 4. Что внутри

| Путь | Назначение |
| --- | --- |
| `src/` | сервер: маршруты, модели, шаблоны, библиотеки |
| `public/` | CSS, JS, шрифты |
| `scripts/` | служебные команды: создание администратора, демо-данные, копии, выгрузка статики |
| `test/` | тесты |
| `deploy/` | конфиги Caddy, nginx, systemd |
| `docs/` | инструкции: ведение сайта, выкладка, устройство, оформления |
| `Dockerfile`, `docker-compose.yml` | запуск в Docker |

Команды: `npm start` (запуск), `npm run dev` (запуск с перезагрузкой при правках), `npm test`, `npm run backup` (копия сейчас).

## 5. Если что-то не работает

- **`npm ci` ругается на версию Node.** Нужен Node 22+. Поставьте с https://nodejs.org и откройте терминал заново.
- **Ошибка сборки `better-sqlite3` или `sharp`.** Обычно из-за старой версии Node или неполной установки. Удалите папку `node_modules` и выполните `npm ci` ещё раз. На Windows при необходимости поставьте «Build Tools for Visual Studio» (пункт «Разработка классических приложений на C++»).
- **Порт 3000 занят.** В `.env` поставьте `PORT=3100` и откройте http://localhost:3100.
- **Не открывается админка после выкладки.** Проверьте, что `SITE_URL` начинается с `https://` и совпадает с адресом в браузере, а `TRUST_PROXY=true` стоит только за прокси.
- **Забыли пароль администратора.** `npm run admin:create -- почта "Имя" новый-пароль` обновляет существующего пользователя.
- **Новости не добавляются сами.** Серверу нужен выход в интернет по https. Кнопка «Обновить сейчас» в разделе «Новости» админки покажет, какой источник не открылся.

## 6. Что не входит в архив

Файл `.env` с паролями, база данных, загруженные фото и папка `node_modules` (ставится командой `npm ci`). Содержимое настоящего сайта хранится в `data/` на том компьютере или сервере, где он запущен: делайте копии (раздел «Копии» в админке).
