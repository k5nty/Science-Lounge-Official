# Устройство проекта

## Почему не Astro + Directus

ТЗ рекомендует статический фронтенд и готовую CMS, но разрешает свой стек, если выполнены требования. Здесь выбрано одно приложение на Node.js:

- один процесс, один файл базы SQLite, один Docker-образ: проще поддерживать ученикам;
- «Опубликовать → сайт обновился» происходит мгновенно, без пересборки и вебхуков;
- админка написана под этот контент, поэтому в ней ровно те поля и подсказки, что в ТЗ;
- нет зависимости от чужих SaaS, всё работает на сервере в России.

Цена: нет статической выдачи. Это закрывается кэш-заголовками, сжатием и малым весом страниц (по Lighthouse на телефоне: Performance 92–95, Accessibility 96–100, SEO 100).

## Слои

```
src/
  server.js          запуск, создание администратора, копии, остановка
  app.js             Express: заголовки безопасности, статика, роутеры
  config.js          переменные окружения
  db.js, migrations.js   SQLite (better-sqlite3), миграции по PRAGMA user_version
  models.js          чтение/запись: выпуски, лекторы, конференции, команда, обращения
  settings.js        настройки сайта (описание полей = форма в админке)
  auth.js            сессии, CSRF
  i18n.js            строки интерфейса RU/EN
  routes/
    public.js        страницы сайта (RU и /en)
    forms.js         POST /forms/* (отзыв, вопрос, предложение, связь, удаление фото)
    feeds.js         .ics, RSS, sitemap, robots, OG-картинки
    admin/*.js       админка
  lib/
    typo.js          типограф (ёлочки, тире, неразрывные пробелы)
    markup.js        безопасный мини-markdown, термины, формулы KaTeX
    images.js        обработка фото (поворот, EXIF прочь, WebP+AVIF)
    og.js            обложки для Telegram (satori + resvg)
    ics.js, video.js, russia.js, telegram.js, backup.js, security.js, csv.js
  views/             шаблоны nunjucks (layouts, partials, pages, admin)
public/              css, js, шрифты
```

## Модель данных

Шесть сущностей из ТЗ плюс служебные:

| Таблица | Назначение |
| --- | --- |
| `issues` | выпуск (лекция): номер, slug, тема RU/EN, дата, место, анонс, конспект, видео, фото, статус, публикация |
| `lecturers` + `issue_lecturers` | лекторы, связь многие-ко-многим |
| `conferences` + `conference_jury` + `conference_photos` | конференции по годам |
| `team` | сооснователи и помощники |
| `feedback` | обращения всех типов, согласие (дата, IP), статус, срок |
| `settings` | настройки сайта |
| `media` | файлы: ширины, alt, автор, согласие |
| `users`, `sessions` | вход в админку |

Время хранится в UTC, показывается по Москве (UTC+3 без перехода).

## Правила, которые держит код

- **Публикация.** Видим выпуск, если `published`, или `scheduled` и время наступило. Черновики и «ждёт даты» отдают 404 в том числе из sitemap, RSS, `.ics`, OG.
- **«Прошедшая».** Через 3 часа после начала, автоматически.
- **Фото.** В галерею и на обложку попадают только фото с согласием «да» или «общий план». «Не проверено» и «нет» не публикуются. Публикация выпуска с фото без alt блокируется (сохраняется как черновик).
- **Формы.** Honeypot, подписанный токен времени (мгновенные отправки отсекаются), лимит по IP. Капчи нет. Согласие обязательно там, где есть контакты, и хранится с датой и IP.
- **Загрузки.** Только изображения (пересобираются через sharp), PDF и MP4/WebM по сигнатуре файла. Оригинал не хранится.
- **Безопасность.** CSP без inline-скриптов, SameSite-cookie, CSRF на всех изменяющих запросах админки, scrypt для паролей, лимит попыток входа.

## Расширение

- Новый тип страницы: роут в `routes/public.js`, шаблон в `views/pages/`.
- Новое поле выпуска: колонка в `migrations.js` (добавьте новую миграцию, старые не правьте), поле в `models.js::saveIssue`, форма `views/admin/issue-form.njk`, разбор в `routes/admin/issues.js`.
- Новая настройка сайта: элемент в `settings.js::SETTINGS_SCHEMA` (форма в админке появится сама).
